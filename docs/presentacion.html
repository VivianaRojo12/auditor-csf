1. La idea

  • Usuario: responsable de seguridad de infraestructura crítica
  • Problema: comparar políticas contra cientos de controles es lento y omite cosas
  • Entrega un informe de brechas por función del CSF 2.0, no una conversación
    estado (cubierto/parcial/ausente), gravedad, evidencia, control citado y redacción corregida
  • Original: auditor + clasificador + generador; cambia entrada (documento) y salida (informe)

2. Arquitectura — contenedores

  • Web (presentación) y Servicio (lógica)
  • La web consume solo la API por HTTP
  • Ollama, ChromaDB y SQLite, todo local

2. Arquitectura — capas del servicio

  • C1 API · C2 Orquestación · C3 Guardrails
  • C4 Caché · C5 Contexto/RAG · C6 Enrutador/Gateway
  • C7 Datos · T1 Observabilidad · T2 Retroalimentación
  • dependencias solo hacia abajo; adaptadores intercambiables

3. Selección de modelos y RAG

  • Comparados 2 embeddings y 3 modelos con evidencia (acierto@k, fidelidad, latencia)
  • Enrutador: ruta simple (modelo rápido) vs. compleja (modelo capaz)
